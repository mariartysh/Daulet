# Court Hunter — бот и панель для ловли кортов в Daulet Tennis

Ищет свободные корты на сайте (Altegio), бронирует их и пишет в Telegram.
Поиск идёт **на сервере**: Telegram и панель можно закрыть.

---

## 1. Почему бот перестал бронировать (разобрано)

Altegio ничего не менял. В диагностике было видно:

```
"задание": { "timeFrom": "24:00", "timeTo": "25:00", ... }
```

Окно старта уехало в **00:00–01:00**: кнопки ± позволяли увести «конец» за полночь,
а «начало» тянулось за ним. Корты бот видел (тест подключения показывал 13),
но под фильтр не попадал ни один слот — отсюда «свободного нет, слежу дальше».

Что сделано, чтобы это не повторилось:

* окно старта не может быть короче **3 часов** — и в панели, и в боте;
* если старое окно было сломано, оно само выправляется при загрузке (24:00–25:00 → 22:00–01:00);
* в панели узкое окно подсвечивается красным;
* дни хранятся **абсолютными датами**: после полуночи «завтра» само становится «сегодня»,
  прошедший день выпадает из плана. Бот больше не сбивается на смене суток.

Если бронь всё же не проходит, точную причину покажет `/api/diag?key=ВАШ_TICK_KEY` —
смотрите поле `подходят_под_окно`. Есть слоты, а там пусто → виноват фильтр, а не сайт.
Ответ `401/403` в шагах → пора обновить ключ (раздел 3).

## 2. Что изменилось в этой версии

**Отдельный доступ для каждого.** Пароль общий (вы его раздаёте), но профиль у каждого свой:
свои контакты, свои охоты, свои брони. Никто не видит чужого.
Вы как владелец (`ADMIN_USERNAME`) видите всех: статус, план, охоты, брони, контакты,
можете остановить чужую охоту, закрыть доступ, выключить бота целиком.
Когда кто-то ловит корт или у кого-то умирает ключ — вам приходит уведомление.

**До 3 охот одновременно** у каждого. Например «сегодня вечер, крытый» и «суббота утро, любой».
Каждая со своими днями, окном, частотой и режимом.

**Массовая бронь на разных людей.** До 5 контактов. Первый — основной.
Если на одно и то же время берём больше одного корта, второй и следующие оформляются
на других людей из списка — администрация отменяет несколько кортов, записанных на одно имя.

**Единица брони — один час.** «Сколько играем» убрано: нужно 2 часа — ставьте «2 корта на день»,
бот возьмёт два соседних часа, если они свободны.

**Частота 2 / 3 / 5 / 7 / 10 секунд**, по умолчанию 3. Вариант «60 с» убран.
Плюс запросы расписания идут **параллельной пачкой** (`PARALLEL=6`), и опрашиваются
только корты и дни из фильтра — полный обход занимает доли секунды вместо нескольких секунд.

**Бот и панель — одно и то же.** Все действия проходят через общий слой (`lib/svc.js`):
остановили в боте — в панели тоже остановлено, и наоборот. Уведомления о находках,
бронях и сбоях приходят в Telegram независимо от того, откуда нажали кнопку.

**Больше не нужно чистить данные перед охотой.** При запуске бот сам сбрасывает
анти-дубли, старые предложения, фантомные брони и перечитывает список кортов.
Панель больше не хранит план локально — единственный источник правды сервер,
поэтому расхождений «в боте одно, в панели другое» нет.

**Кнопки обслуживания** («Проверить сейчас», «Тест подключения», «Очистить данные»)
переехали отдельным блоком в самый низ панели.

## 3. Обновить ключ Altegio (`ALTEGIO_AUTH`) — делать при 401/403

Ключ живёт, пока живёт сессия на сайте кортов. Умер — брони не проходят.

1. Откройте `https://tennisdaulet.altegio.me` в Chrome на компьютере.
2. `F12` → вкладка **Network** → фильтр **Fetch/XHR**.
3. На сайте выберите любой корт и дату, чтобы подгрузилось расписание.
4. В списке запросов найдите любой к `api.alteg.io` (например `book_times/...`).
5. Клик по нему → вкладка **Headers** → блок **Request Headers** → строка `authorization`.
6. Скопируйте **всё значение целиком**, включая слово `Bearer` и пробел:
   `Bearer gtcwf654agufy25gsadh`
7. Vercel → ваш проект → **Settings** → **Environment Variables** → `ALTEGIO_AUTH` → **Edit** →
   вставьте новое значение → **Save**.
8. Vercel → **Deployments** → у верхнего деплоя «…» → **Redeploy** (иначе переменная не подхватится).
9. Проверка: в панели «Тест подключения» должен показать `✅ кортов 13`.

Если в том же запросе есть заголовок `x-partner-token` или `x-user-token` — пришлите их мне,
добавлю в клиент: значит, сайт перешёл на партнёрскую схему авторизации.

## 4. Что поменять в сторонних сервисах (по шагам)

### 4.1 Vercel → Settings → Environment Variables

**Добавить новые** (Add New, значение как указано):

| Переменная | Значение | Зачем |
|---|---|---|
| `DEF_INTERVAL` | `3` | частота по умолчанию для новой охоты, сек |
| `PARALLEL` | `6` | сколько запросов расписания отправлять одновременно |
| `COMBO_CAP` | `24` | максимум «корт × день» за один проход (было 8) |
| `MAX_HUNTS` | `3` | охот одновременно у одного человека |
| `MAX_CONTACTS` | `5` | контактов в списке для массовой брони |

**Проверить существующие:**

* `ALTEGIO_AUTH` — свежий (раздел 3).
* `APP_URL` — точный адрес панели, **без слэша на конце**. Без него фоновый поиск не работает.
* `ADMIN_USERNAME` — ваш ник в Telegram без `@`. Именно этот аккаунт становится админом.
* `TICK_KEY` — им же подписываются личные ссылки на панель. **Если поменяете — все ссылки
  «Открыть панель» в старых сообщениях перестанут работать**, друзьям надо нажать /menu заново.
* `TZ_OFFSET` = `5`, `COMPANY_ID` = `521176`.

После правок — **Redeploy**.

### 4.2 Upstash (Redis)

Делать ничего не нужно. При первом запросе бот сам переносит старые данные
в новую схему: ваш профиль и брони становятся профилем владельца, остальные подключённые чаты —
отдельными пользователями с пустыми охотами. Старый ключ `autobook:state` не удаляется,
так что откат возможен.

Новые ключи: `ch:g` (общее), `ch:u:<id>` (по пользователю), `ch:hb:a|b` (ветки).

### 4.3 cron-job.org (внешний будильник, обязателен)

Один job, ничего менять не нужно, но проверьте:

* **URL**: `https://ВАШ-АДРЕС/api/tick?key=ВАШ_TICK_KEY`
* **Schedule**: Every 1 minute
* **Save responses**: включено (чтобы видеть ответы в History)
* В **History** должны быть ответы `200` с телом вида
  `{"ok":true,"alive":["a","b"],...}`. Если `401` — не совпадает `TICK_KEY`.
  Если `404` — неверный адрес. Если пусто — job выключен.

### 4.4 Telegram (@BotFather)

Ничего менять не нужно. Вебхук остаётся прежним. Если бот молчит — переустановите вебхук,
открыв в браузере (подставьте свои значения):

```
https://api.telegram.org/botТОКЕН/setWebhook?url=https://ВАШ-АДРЕС/api/telegram&secret_token=ВАШ_TG_SECRET
```

Ответ должен быть `{"ok":true,...}`.

### 4.5 Vercel Deployment Protection

Должна быть **выключена** (Settings → Deployment Protection → Disabled).
Иначе cron-job.org и самовызовы получают страницу логина вместо API.

## 5. Как выдать доступ друзьям

1. Дайте человеку ссылку на бота и пароль (`APP_PASSWORD`, он же виден в админ-панели).
2. Человек присылает боту пароль одним сообщением → получает свой профиль.
3. Дальше он всё делает сам: контакты → охота → запуск.
4. Кнопка «📱 Открыть панель» в боте у каждого своя — она содержит личную подпись,
   по ней панель понимает, кто пришёл. Пароль в панели больше не нужен.
5. Сменить пароль: в боте `/key НовыйПароль`. Уже подключённые не отваливаются.
6. Закрыть доступ: Админ-панель → «🚫 Отключить @ник». Его охоты остановятся.

Вход в панель с компьютера, вне Telegram, по паролю доступен **только вам** (владельцу) —
остальным панель открывается кнопкой из бота.

## 6. Про скорость честно

Что упирается в физику:

* один запрос к Altegio — это 150–400 мс сетевого времени;
* сузили опрос до кортов из фильтра и отправляем пачкой по 6 → полный обход
  13 кортов занимает ~0,5 с вместо ~4 с;
* поэтому реально работающий минимум — **2 секунды**. Ставить меньше бессмысленно:
  предыдущий обход ещё не закончился.

Чем ниже темп, тем выше риск: Altegio отдаёт `429 Too Many Requests` (лимит по ключу и IP)
или `403`. Бот это ловит, автоматически сбавляет темп, пишет вам в Telegram и возвращается
к выбранной частоте, когда отпустит. Заголовки запросов теперь браузерные, User-Agent
ротируется — одинаковый «отпечаток» на высокой частоте ловит бан быстрее всего.

«Меньше секунды», как у конкурентов, с одного сервера и одного ключа не выйдет.
Так делают через несколько IP и несколько ключей параллельно. Если это нужно —
это отдельная задача: пул прокси плюс несколько ключей, скажите, распишу.

**Что даёт больше, чем частота:** узкий фильтр (конкретный корт + конкретный день —
1 запрос вместо 39) и режим «Брать сразу» вместо «Спросить меня»: пока вы читаете
уведомление, слот уводят.

## 7. Проверка после деплоя

1. Панель открывается из бота кнопкой «📱 Открыть панель», пароль не спрашивает.
2. «Тест подключения» → `✅ кортов 13`.
3. Добавьте контакт (имя + телефон), запустите охоту.
4. В журнале («Что делает бот») идут строки «проверка №…» с интервалом ~3 с.
5. `/api/diag?key=…` → `живые_ветки: ["a","b"]`.
6. В боте нажмите «⏹ Стоп» → в панели охота сразу показана как остановленная (обновление раз в 7 с).
7. cron-job.org → History → `200`.

## 8. Задел под подписку

Сделано на уровне архитектуры (реализации оплаты нет, как договорились):

* у каждого пользователя своя запись в `ch:g → users[]` c полем `plan`;
* в `lib/svc.js` есть таблица `PLANS` и функции `planOf(row)` / `limits(row)`;
  сейчас `free` и `pro` одинаковы — никто не ограничен;
* `startHunt` уже сверяется с лимитом «сколько охот одновременно» и минимальной частотой.

Чтобы включить платный режим:

1. В `PLANS.free` поставьте, например, `{ hunts: 1, minInterval: 10, contacts: 1 }`,
   в `PLANS.pro` оставьте текущие значения.
2. После оплаты (Kaspi перевод, вы подтверждаете вручную) присвойте человеку
   `row.plan = { tier: 'pro', until: Date.now() + 30*86400e3 }`.
   Удобнее всего добавить это кнопкой в админ-панель — скажите, добавлю.
3. Когда `until` проходит, `planOf` сам возвращает `free` — подписка гаснет без крона.

Что стоит сделать до продаж (мои предложения, по приоритету):

1. **Экран тарифа в панели**: что даёт pro, сколько осталось дней, кнопка «Оплатить».
2. **Пробный период**: первые 7 дней всем `pro`, дальше `free` — люди должны один раз
   почувствовать разницу в скорости.
3. **Онбординг**: сейчас человек попадает в панель и должен сам догадаться про контакты.
   Нужны 3 шага с проверкой готовности и кнопкой «Запустить».
4. **История**: «поймано кортов за месяц», «сэкономлено времени» — это то, что продаёт продукт.
5. **Свой ключ у каждого пользователя.** Сейчас все ходят через один `ALTEGIO_AUTH`:
   это и есть главный риск бана при росте. Для продаж нужно, чтобы каждый подключал свой,
   либо чтобы был пул ключей с распределением.
6. **Другие клубы**: `COMPANY_ID` вынести в настройку пользователя, а не в переменную окружения.
   Тогда один бот обслуживает любые залы на Altegio — это и есть настоящий рынок.

```

api/tick.js       фоновый поиск: звенья цепочки + пингер
api/diag.js       диагностика
lib/svc.js        общий слой действий (бот и панель зовут его)
lib/hunt.js       ядро охоты: поиск, бронь, отмена, напоминания
lib/altegio.js    клиент API кортов (браузерные заголовки, параллельные пачки)
lib/store.js      хранилище: общее + по пользователю
lib/logic.js      время, даты, окна, дедлайны
lib/chain.js      фоновые ветки A/B
lib/tg.js         Telegram Bot API
public/index.html панель (мини-приложение)
```
